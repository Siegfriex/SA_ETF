## 2. 셀 대응과 분모

- 원문 Table 1–6 = 45개 조건 행 × n∈{500, 1000, 2000} = **135셀**. YAML 전사와 PDF 38–39쪽 `pdftotext` 를 대조했다.
- 셀당 값: 요청 반복 `reps`, 실패 `failed`, 기각 `rejections`, **조건부 기각률** `rate_cond_ok = rejections / (reps − failed)`, 실패율 `fail_rate`, Wilson 95% CI (성공 반복 기준).
- size 셀 = 각 표의 'size' 행 (H0), power 셀 = 나머지 (H1). 두 종류를 한 평균에 섞지 않는다.
- 실패 처리: 실패를 기각 없음으로 몰아넣지도, 조용히 빼지도 않는다. 셀마다 실패율과 조건부 기각률을 따로 적는다.
  - 기존 `summarize_mc.py` 의 `reject_rate_all` 은 실패를 비기각으로 센 값으로, 라벨이 붙어 있다.
  - 이전 최종 보고서의 레인별 수치는 `reject_rate_ok` (= 조건부) 기준이었다.

## 4. 실패 72건 (raise 레인)
- 33개 행에 분산돼 있다 (최다 `t5_alpha_n04_beta_05` 6건).
- 같은 (case, n, rep) 의 clip 결과: 평균 T=0.910, 최대 2.542, 기각 4/72.
  - clip 이 비양수 분산을 machine eps 로 바꾸면 거대한 잔차 하나가 τ̂² 와 경로를 지배한다. 그래서 통계량이 대체로 1 근처로 눌린다.
  - 다만 항상 그런 것은 아니다 (최대 2.54).
- 실패율이 1.6% 라서, clip 처리가 Tables 재현 실패의 주 원인은 아니다.

## 5. 같은 입력 위의 비교 (paired) 인가
- clip·raise·recursive 레인은 seed 를 `sha256(master_seed, case_id, n, rep, "dgp")` 로 파생한다. 레인 이름이 seed 에 들어가지 않는다. 조인한 4500쌍 모두 `dgp_seed` 가 같다.
- **seed 가 같다는 것만으로 입력 경로가 같다고 가정하지 않았다.** 확인 방법은 두 가지다.
  - MC 레인 경로로 시계열을 다시 생성해, ablation 이 저장한 npz 와 sha256 을 비교했다: 15/15 일치 (5개 조건 × 3개 반복).
  - ablation 의 모든 추정 변형은 저장된 같은 배열을 읽는다. 결과 행마다 `dgp_sha256` 를 기록하고, 요약에서 `paired_same_dgp_input` 로 검사한다.
- 예외: Table 6 수정 행의 수정 전 chunk 는 post-change 파라미터가 달라 입력 경로가 다르다 (변화 시점 이후).
- A(clip) 대 B(recursive), n=500, 같은 반복 0–99 의 McNemar (정확검정):

  | | 쌍 | A 만 기각 | B 만 기각 | p |
  |---|---|---|---|---|
  | size | 500 | 0 | 18 | 7.6e-6 |
  | power | 4000 | 51 | 720 | 3.6e-152 |

  두 정책은 같은 시계열에서 통계적으로 확실히 다른 판정을 낸다.
